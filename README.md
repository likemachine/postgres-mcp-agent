# postgres-analyst

Автономный агент-аналитик PostgreSQL на Kotlin и Eclipse ARC. Агент отвечает на вопросы на русском языке о схеме и данных БД, обращаясь к ней только через MCP-сервер в режиме «только чтение».

## Архитектура

```text
Arc View (GraphQL)
      |
Kotlin / ARC agent  (postgres-analyst, порт 5051)
      |-- Ollama: qwen2.5-coder:7b
      |-- JsonToolAdapter (текстовый JSON-протокол вызова инструментов)
      |
MCP-сервер (Python, FastMCP, SSE, 127.0.0.1:5050)
      |
PostgreSQL 16 (Docker, роль mcp_readonly)
```

## MCP-инструменты

`list_tables`, `describe_table`, `get_table_stats`, `run_select_query`, `explain_query`, `get_db_health`.

## Безопасность (два независимых слоя)

1. Валидатор SQL в MCP: допускаются только `SELECT` и `WITH ... SELECT`. Остальное возвращает `SELECT_ONLY`; обращения к чужим таблицам возвращают `TABLE_NOT_ALLOWED`.
2. Права роли `mcp_readonly` в PostgreSQL: нет `INSERT/UPDATE/DELETE/TRUNCATE`, нет `CREATE` в схеме `public`.

Проверено: запросы «Удали всех клиентов», `DROP TABLE orders`, `UPDATE clients ...` отклонены, данные не изменены (20 клиентов, 200 заказов).

## Запуск

```bash
# MCP-сервер
cd mcp && set -a && . ./.env && set +a
nohup ./.venv/bin/fastmcp run server.py --transport sse --host 127.0.0.1 --port 5050 >> mcp-run.log 2>&1 &

# Агент
cd postgres-analyst && ./gradlew bootJar -x test
nohup java -jar build/libs/postgres-analyst-0.1.0.jar >> arc-run.log 2>&1 &

# Бенчмарк
python bench.py --only analytics no_data --repeat 3 --url ws://localhost:5051/subscriptions
```

## Известные проблемы

- Агент иногда отвечает без обращения к БД (пометка `none, no tools were called`) и выдаёт выдуманное число. Пример: «Клиент с наибольшей выручкой» давал то Client 1 (203170.00, без вызовов), то верного Client 20 (196990.00, с `run_select_query`). Доля таких ответов в серии из 50 запусков: ___ из 50.
- Механизм напоминания в адаптере основан на ключевых словах, подобранных под тестовый набор; для новых формулировок вопросов он может не сработать.
- Промпт задан и в `AgentConfiguration.kt`, и в YAML; нужен один источник.
- К ответу пользователя дописывается технический блок `MCP calls verified by server` с полным SQL.
- Подсказки по схеме (формула выручки, связи таблиц) заданы в промпте, а не в БД.
- Модель 7B недетерминирована: один вопрос может дать разные пути выполнения.
- Лимит цикла инструментов: 8 шагов.
- В терминале Windows при вставке кириллицы теряется старший байт; файлы с русским текстом нужно копировать через `scp`.

## Планы

- регистрация агента в LMOS (capabilities: `postgresql`, `sql`, `analytics`, `data`), маршрутизация вопросов о данных.
- Проверка перед ответом: числа в ответе должны присутствовать в результатах инструментов.
- Снижение температуры модели, оценка более крупной модели с нативным вызовом инструментов.
- Комментарии `COMMENT ON` в схеме БД вместо подсказок в промпте.
- Отдельный контрольный набор вопросов, не использованных при настройке.
